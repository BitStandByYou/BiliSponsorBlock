## 2. DexKit 兜底（被混淆的锚点）

以下锚点是**混淆短名**，随版本重排：`seek.v3.g` / `seek.v3.f`、`mine.d`。

实现见 `host/DexKitResolver.kt`：

- **真名/候选名优先**：候选全部存在时**完全跳过** DexKit（零开销，`DexKitBridge.create` 很贵）。
- 候选落空时才创建桥，按**结构条件**定位：
  - seekTrack：包前缀 `com.bilibili.playerbizcommonv2.widget.seek.v3.` + 父类 `android.graphics.drawable.Drawable`
    + 声明 `draw(android.graphics.Canvas)`。
  - mineAdapter：包前缀 `tv.danmaku.bili.ui.main2.mine.` + 父类 `RecyclerView$Adapter` + 字段类型 `java.util.List`。
- 结果写入 `ResolvedTargets`，供 Hook 安装读取；桥用 `.use {}` 自动释放。

## 3. 其它国内版差异

- 模块日志 TAG：`BiliSB`。
- 宿主数据目录：`/data/data/tv.danmaku.bili`（JSON 镜像 / 统计文件）。
- 模块**无桌面图标**：设置 UI 在宿主进程内以 Dialog 呈现（`SponsorBlockSettingDialog`），
  不依赖 `LauncherActivity`，也不需要模块自身进程常驻。
